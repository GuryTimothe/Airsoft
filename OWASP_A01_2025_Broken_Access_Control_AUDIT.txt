==================================================
2) CE QUE TU N'AS PAS OU A RENFORCER
==================================================

[PARTIEL] Journalisation/alerte des echec d'autorisation
- OWASP recommande de logguer les refus d'acces et d'alerter en cas de repetition.
- Je n'ai pas trouve de config explicite de canal/strategie dediee a ces evenements.
- Impact: detection d'attaque plus faible.

[PARTIEL] Couverture de tests d'acces inegale selon endpoints
- Il y a des tests d'autorisation, mais certains endpoints sensibles sont surtout testes en "happy path".
- Exemple notable: exports admin (tests positifs presents, peu/pas de tests 401/403 explicites).
- Fichier concerne:
  - backend/tests/Api/AdminExportControllerTest.php

[PARTIEL] Politique JWT "short-lived" non explicite dans la config
- OWASP recommande des JWT courts + strategie claire refresh/revocation.
- Ici, la revocation est bien geree, mais le token_ttl n'est pas explicitement defini dans lexik_jwt_authentication.yaml.
- Fichier:
  - backend/config/packages/lexik_jwt_authentication.yaml

[PARTIEL] CORS configure globalement
- CORS est parametre via variable d'env (bien), mais applique sur '^/' avec tous les verbes API.
- Selon OWASP, minimiser CORS au strict necessaire (origines + routes les plus restreintes possible).
- Fichier:
  - backend/config/packages/nelmio_cors.yaml

[A VERIFIER HORS CODE APP] Durcissement serveur web (directory listing, fichiers sensibles)
- OWASP cite: desactiver listing de dossiers, eviter exposition .git/backups/meta dans webroot.
- Ce point depend surtout de Nginx/Apache/reverse proxy et pipeline de deploiement.
- Non verifiable completement depuis le code applicatif seul.

==================================================
3) VERDICT RAPIDE
==================================================

Niveau actuel sur A01: SOLIDE mais pas complet.
- Points forts: controles serveur centralises, voters, filtrage de visibilite/ownership, deny-by-default, revocation JWT.
- Principaux gaps: observabilite securite (logs/alertes), tests negatifs supplementaires, explicitation TTL JWT, CORS encore plus restrictif, hardening infra web.

==================================================
4) PRIORITES CONSEILLEES (ordre)
==================================================

1. Ajouter des tests 401/403 sur endpoints admin/export et autres routes sensibles. (on le fait)
2. Mettre une journalisation securite explicite pour les refus d'acces + seuil d'alerte.
3. Definir explicitement la duree de vie JWT (et documenter la politique refresh/revocation). (on le fait)
4. Restreindre CORS par route/origine/methode au minimum requis. (on le fait peut être)
5. Valider en infra: directory listing OFF, pas de fichiers sensibles exposables sous web root.
