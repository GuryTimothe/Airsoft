==================================================
1) CE QUE TU AS (OK)
==================================================

[OK] Requetes DB parametrees (Doctrine QueryBuilder)
- Requetes faites via QueryBuilder + setParameter, sans concatenation SQL utilisateur.
- Fichiers:
  - backend/src/Repository/UserRepository.php
  - backend/src/Repository/GameRepository.php
  - backend/src/Repository/GameRegistrationRepository.php

[OK] Pas de patterns critiques detectes dans le code applicatif backend
- Aucune occurrence detectee de exec/shell_exec/system/popen/proc_open/eval/unserialize dans backend/src.
- Limite fortement le risque d'OS command injection/eval injection.

[OK] Validation serveur presente sur DTO/entites
- Beaucoup de contraintes Symfony Validator (NotBlank, Length, Regex, Email, Choice, etc.).
- Validation explicite avant persistence sur certains processors.
- Fichiers:
  - backend/src/Dto/*.php
  - backend/src/Entity/*.php
  - backend/src/State/GameRegistrationCreateProcessor.php
  - backend/src/State/RegisterProcessor.php

[OK] Validation cote frontend presente
- Schemas Zod + react-hook-form pour filtrer en amont.
- Fichiers:
  - frontend/src/lib/schemas/auth.ts
  - frontend/src/components/auth/AuthForm.tsx

[OK] Pas de pattern XSS React a haut risque detecte
- Pas de dangerouslySetInnerHTML ni innerHTML direct dans frontend/src.
- React echappe les sorties textuelles par defaut.

[OK] SAST present dans le repo (Semgrep)
- Workflow de scan securite present avec regles OWASP.
- Fichier:
  - .github/workflows/security-scanner.yml

==================================================
2) CE QUE TU N'AS PAS OU A RENFORCER
==================================================

[PARTIEL] Absence de tests d'injection dedies (SQLi/Command/XSS fuzz)
- Pas de batterie explicite de tests payloads malveillants (fuzz sur params, headers, body, etc.) visible dans les tests.
- OWASP A05 recommande revue code + tests automatises/fuzz.

[PARTIEL] Risque de CSV Injection (Formula Injection)
- Les exports CSV incluent des valeurs utilisateurs (nom, email, pseudo, etc.) sans neutralisation explicite des prefixes de formule (=,+,-,@).
- Risque: execution de formules lors d'ouverture dans Excel/LibreOffice.
- Fichier:
  - backend/src/Controller/AdminExportController.php

[PARTIEL] Validation positive presente mais non centralisee par type de champ
- La validation est globalement bonne, mais une politique centralisee de sanitization/encoding par contexte (HTML/CSV/headers) n'est pas formalisÃ©e dans le repo.

[PARTIEL] SAST non clairement branche comme gate bloquant du pipeline principal
- Le workflow security-scanner existe, mais son integration obligatoire au pipeline principal doit etre verifiee/renforcee.

[A VERIFIER] Injection via couches externes
- A verifier en environnement reel avec DAST sur API exposee (params, entetes, cookies, JSON, query strings) pour completer la couverture source-code.

==================================================
3) VERDICT RAPIDE
==================================================

Niveau actuel sur A05: BON sur la prevention backend classique (ORM + validations), mais couverture a completer sur tests offensifs et encodage de sortie specifique (CSV).

Points forts:
- pas de raw SQL/exec/eval detectes
- validation serveur et frontend en place
- pas de patterns XSS React evidents

Gaps principaux:
- pas de suite d'attaque injection dediee (fuzz/DAST)
- risque CSV formula injection non traite explicitement
- securite statique a rendre explicitement bloquante dans CI

==================================================
4) PRIORITES CONSEILLEES (ordre)
==================================================

1. Ajouter des tests d'injection automatises (payloads SQLi, XSS, command-like, headers/query/body).
2. Corriger les exports CSV pour neutraliser les cellules commencant par =, +, -, @.
3. Rendre le security scan (Semgrep) bloquant dans le pipeline principal.
4. Ajouter un job DAST leger sur endpoints critiques (auth, register, exports, filtres query).
5. Documenter une politique d'encoding/sanitization par contexte (HTML, JSON, CSV, headers).
