==================================================
2) CE QUE TU N'AS PAS OU A RENFORCER
==================================================

[MANQUANT] Threat modeling formel (STRIDE / misuse-cases)
- Pas de document de modelisation de menace formelle par flux critique (auth, inscription, exports, admin).
- Les menaces sont evoquees, mais pas tracees en artefact de design versionne.

[PARTIEL] Exigences securite traceables de bout en bout
- Les exigences existent de maniere diffuse (docs + code + tests), mais pas de matrice unique
  "exigence -> controle design -> test -> evidence CI" pour chaque flux critique.

[PARTIEL] Tests d'abus orientes design
- Les tests couvrent bien de nombreux cas fonctionnels/securite, mais pas de suite dediee
  "misuse-case"/"abuse-case" systematique (bot abuse, enchainements anormaux, contournement workflow).

[PARTIEL] Protection anti-automatisation metier
- Rate limiting present sur login/register.
- Pas de strategie anti-bot/anti-abus metier plus large visible pour les operations potentiellement
  massives (ex: scenarios d'automatisation metier, burst patterns hors auth).

[PARTIEL] Gouvernance Secure SDLC formalisee
- Presence de CI, checklists et scan securite, mais pas de standard explicite de type
  "Definition of Done securite" obligatoire avec revues de design securite avant livraison.

==================================================
3) VERDICT RAPIDE
==================================================

Niveau actuel sur A06: BON sur les controles metier implementes dans le code, mais MOYEN sur la formalisation
Secure-by-Design (threat modeling, exigences securite tracees, misuse-cases).

Forces:
- workflows critiques securises par regles metier explicites
- autorisation solide (RBAC + Voters)
- anti-abus initiale (rate limiting login/register)

Gaps principaux:
- manque d'artefacts de design securite formels
- couverture abuse-case non systematique
- governance secure design perfectible

==================================================
4) PRIORITES CONSEILLEES (ordre)
==================================================

1. Produire un threat model formel (STRIDE) pour 4 flux critiques: login, register, game registration, exports admin. (ouais à voir)
2. Creer une matrice de tracabilite securite: exigence -> controle -> test -> preuve CI.
3. Ajouter une suite de tests misuse/abuse-cases (automatises) sur workflows metier critiques. (pourquoi pas)
4. Etendre l'anti-abus au-dela de l'auth (quotas/frequence par operation metier sensible). (on le fait)
5. Ajouter une gate de revue "security design" dans le process de PR (template + checklist DoD securite).
