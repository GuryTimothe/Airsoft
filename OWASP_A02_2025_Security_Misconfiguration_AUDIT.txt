Audit OWASP A02:2025 - Security Misconfiguration
Date: 2026-07-18
Perimetre: backend Symfony/API Platform + frontend Next.js + Docker Compose

Reference:
https://owasp.org/Top10/2025/A02_2025-Security_Misconfiguration/

==================================================
1) CE QUE TU AS (OK)
==================================================

[OK] Configuration centralisee via variables d'environnement
- Les secrets/parametres sensibles passent par des variables d'env (APP_SECRET, JWT_*, DB, REDIS, etc.).
- Fichiers:
  - .env.example
  - docker-compose.yaml
  - backend/config/packages/framework.yaml
  - backend/config/packages/lexik_jwt_authentication.yaml

[OK] Fichiers locaux sensibles ignores par Git
- .env local, cles JWT PEM, vendor, var, etc. sont ignores.
- Fichiers:
  - .gitignore
  - backend/.gitignore
  - frontend/.gitignore

[OK] Durcissement partiel des conteneurs (non-root)
- Backend et frontend tournent avec un utilisateur non-root dans les images.
- Fichiers:
  - backend/Dockerfile
  - frontend/Dockerfile

[OK] Separation des composants (segmentation de base)
- Services distincts: frontend / backend / postgres / redis.
- Fichier:
  - docker-compose.yaml

[OK] CORS non ouvert en wildcard brut
- Origine pilotee par variable d'env regex (pas de * explicite).
- Fichier:
  - backend/config/packages/nelmio_cors.yaml

[OK] Erreur d'authentification de login generic
- Message non verbeux sur echec de login.
- Fichier:
  - backend/src/Security/Jwt/GenericAuthenticationFailureHandler.php

==================================================
2) CE QUE TU N'AS PAS OU A RENFORCER
==================================================

[MANQUANT] Security headers HTTP explicites
- Je ne trouve pas de configuration applicative pour:
  - Content-Security-Policy
  - Strict-Transport-Security
  - X-Frame-Options
  - X-Content-Type-Options
  - Referrer-Policy
  - Permissions-Policy
- Impact: surface de misconfiguration plus large cote client/navigateur.

[MANQUANT] Politique HTTPS forcee au niveau applicatif
- Pas de requires_channel: https en access_control, ni mecanisme equivalent visible ici.
- Impact: dependance complete a l'infra externe pour eviter trafic non chiffre.
- Fichier concerne:
  - backend/config/packages/security.yaml

[PARTIEL] CORS trop global
- Regle appliquee a '^/' avec tous les verbes API.
- Plus sur de restreindre par routes/origines/methodes strictement necessaires.
- Fichier:
  - backend/config/packages/nelmio_cors.yaml

[PARTIEL] Surface d'exposition API docs/dev features
- API Platform est active sans override prod visible pour desactiver docs/UI si non necessaires.
- Pas de fichier when@prod de hardening detecte dans config/packages.
- Fichiers:
  - backend/config/packages/api_platform.yaml
  - backend/config/bundles.php

[PARTIEL] Processus de hardening "prod" non fige dans cette stack
- Les conteneurs lancent des serveurs dev:
  - backend: php -S
  - frontend: npm run dev
- C'est pratique en dev, mais pas une baseline durcie prod.
- Fichiers:
  - backend/Dockerfile
  - frontend/Dockerfile

[PARTIEL] Risque de credentiels par defaut si non changes
- Valeurs de demarrage existent dans les exemples/docs (ChangeMe.../admin seed).
- Si reprises telles quelles en environnement reel: risque A02 direct.
- Fichiers:
  - .env.example
  - backend/compose.yaml
  - backend/migrations/Version20260714110000.php

[PARTIEL] Gestion centralisee des erreurs a verifier/renforcer
- Tu as des handlers/metiers propres sur certains flux, mais pas de preuve explicite d'une politique globale uniforme de masquage/normalisation de toutes les erreurs techniques.
- Risque: fuite d'info si APP_DEBUG mal positionne ou exception non maitrisee.

[A VERIFIER HORS REPO] Durcissement serveur/reverse proxy
- OWASP A02 insiste sur:
  - directory listing desactive
  - suppression pages/samples inutiles
  - config TLS/ciphers/trusted proxies
- Ces points ne sont pas pleinement auditables sans config Nginx/Apache/Ingress et cible prod.

==================================================
3) VERDICT RAPIDE
==================================================

Niveau actuel sur A02: MOYEN / CORRECT EN DEV, A DURCIR POUR PROD.

Points forts:
- env vars + secrets non hardcodes dans le code applicatif
- separation des services
- execution non-root dans les images

Principaux gaps:
- headers de securite absents dans la config visible
- HTTPS non force au niveau app
- CORS encore large
- stack docker orientee dev (php -S / npm run dev)
- risque de defaults si placeholders non remplaces

==================================================
4) PRIORITES CONSEILLEES (ordre)
==================================================

1. Ajouter des security headers (idealement via reverse proxy + tests automatiques). (à voir)
2. Forcer HTTPS en prod (redirection + requires_channel/ou equivalent infra). (on le documente)
3. Restreindre CORS par route/methode/origine, pas globalement sur '^/'. (on le fait peut être)
4. Desactiver docs/UI API Platform en prod si non necessaires.
5. Remplacer et auditer toutes valeurs par defaut (DB/JWT/admin seed) dans chaque environnement. (à voir)
6. Passer a une stack runtime prod (pas php -S, pas next dev) et documenter une baseline de hardening reproductible.
